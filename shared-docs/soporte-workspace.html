Estado C2C Soporte

El proyecto workspace/c2c-soporte ya cuenta con base documental, backend inicial, database local, scripts de copia controlada y frontend inicial.

La estructura contempla backend, frontend, database, scripts, infra y docs.

El manual primario de usuario y validacion esta en workspace/c2c-soporte/docs/15-manual-usuario-primario.md.

La normalizacion de querys y componentes rescatados desde layoutExample esta documentada en workspace/c2c-soporte/docs/20-normalizacion-querys-layoutExample.md.

El nuevo mapa de producto para modulos, mantenedores, diseno y pruebas esta en workspace/c2c-soporte/docs/21-mapa-modulos-c2c-helpdesk.md, docs/22-plan-mantenedores-c2c-helpdesk.md y docs/23-plan-diseno-pruebas-c2c-helpdesk.md.

El plan de optimizacion de querys para reducir timeouts y esperas excesivas esta en workspace/c2c-soporte/docs/24-plan-optimizacion-querys.md.

La primera optimizacion local creo indices y caches de lectura en rr_gestion_soporte; la evidencia esta en workspace/c2c-soporte/docs/bitacora/2026-05-16-optimizacion-querys-local.md.

El modulo Procesos permite refrescar caches locales manualmente; la bitacora esta en workspace/c2c-soporte/docs/bitacora/2026-05-16-refresco-caches.md.

Modulos frontend activos: Torre de Control, Empresas, Cajeros/Devices, Documentos, Folios/CAF, Rangos SII y Alertas. Todo opera en modo lectura sobre objetos locales rr_gestion_soporte.

Stack definido para C2C

  • Backend: Node.js, Express, TypeScript, Zod, Pino y PostgreSQL con pg.
  • Frontend inicial: React, Vite, TypeScript y CSS local.
  • UI posterior evaluable: Tailwind, TanStack Query, TanStack Table y Recharts.
